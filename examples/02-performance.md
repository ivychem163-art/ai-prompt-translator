# 样例 02：网站太慢了，还有点丑

测试重点：把模糊说法量化，并给用户没提供的数字标上"（建议值，需确认）"。

## 口语原话

> 我的网站太慢了，打开要等半天，而且看着有点丑，能不能弄一下。

## 第一轮期望要点

- **我理解的需求**分成两个模块：性能、视觉。
- **需要确认的问题**可能包括：
  - 网站用什么技术做的：WordPress / React 等框架 / 不清楚（✅ 建议回答"不清楚"时先做诊断）
  - "丑"具体指哪里：配色 / 排版 / 整体改版
  - 能不能改服务器配置：能 / 不能
- **风险和遗漏**应提到：没有现状数据（先测量再优化）、改版可能影响 SEO、需要保留原站备份。
- 以固定句结尾。

## 模拟用户回答

> 1 选 React，2 是配色和排版，3 没回答

## 第二轮期望要点

- 最终指令开头写明"以下按默认建议：Q3"。
- "太慢了"被量化为可测指标，并带标注，例如：
  - 首屏加载 ≤ 2 秒（建议值，需确认）
  - Lighthouse 性能分 ≥ 90（建议值，需确认）
- "有点丑"被拆成具体改动：统一配色（不超过 3 种主色）、正文字号 ≥ 16px、统一行距与间距。
- 验收清单包含"优化前后测速数据对比"。
- 用户没给过的每个数字都带"（建议值，需确认）"。
