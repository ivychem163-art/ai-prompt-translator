# 样例 01：像小红书一样的记账网页

测试重点：把"像XX一样"拆成具体功能清单。

## 口语原话

> 我想做个记账的网页，就是那种像小红书一样好看的，每天花了多少钱能记一下，然后月底能看看钱都花哪了，最好手机上也能用，数据别丢了就行。

## 第一轮期望要点

- **我理解的需求**至少分出这几个模块：记账录入、月度统计、界面风格、手机适配、数据保存。
- **需要确认的问题** ≤ 5 个，每个都有一个 ✅ 建议，可能包括：
  - 数据存在哪：浏览器本地 / 云端账号（✅ 建议先存本地，省去登录）
  - 统计图形式：饼图 / 柱状图 / 两者都要
  - 分类：固定分类 / 允许自定义
- **风险和遗漏**应提到：清理浏览器数据后本地记录会丢失、需要导出备份、金额精度（小数）。
- 以固定句结尾："可以逐条回答，也可以直接回复"按建议来"。"

## 模拟用户回答

> 按建议来

## 第二轮期望要点

- "像小红书一样"被拆成至少 3 条可验证的功能，例如：
  - 双列卡片流展示每笔记录
  - 卡片有分类图标、金额、备注、日期
  - 圆角卡片 + 浅色背景 + 统一主题色
- "手机上也能用"被量化，例如"屏宽 375px 下无横向滚动"。
- 执行方案：均衡档模型（Sonnet 5）、中等思考强度；模块 ≥ 4，应建议分批并写出每批的交付物。
- 原话覆盖核对表中，每句原话（好看、每天记、月底看、手机能用、数据别丢）都有对应位置。
- 验收清单全部是 `- [ ]` 格式。
